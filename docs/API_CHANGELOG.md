# API Changelog — ERP v2

> **Format:** every additive or breaking HTTP change gets one row.
> Minor wording changes don't. Schema drift in an event payload is
> an event-version bump, not a row here.
>
> **Source of truth:** `docs/openapi/erp.json` (CI-dumped per merge).
> This changelog is the human-readable summary; the OpenAPI document
> is the machine contract.

| Wave | Date | Route / Event | Change | Backwards compatible? |
|------|------|---------------|--------|-----------------------|
| W0   | 2026-07-11 | `GET /health` | **Added.** Liveness probe; no DB call; excluded from observability middleware. | Yes (additive) |
| W0   | 2026-07-11 | `GET /ready` | **Added.** Readiness probe; pings DB; reports outbox + Kafka producer status as informational fields. Returns 503 with a JSON body describing the unhealthy dependency. | Yes (additive) |
| W0   | 2026-07-11 | `GET /metrics` | **Added.** Prometheus scrape endpoint. Exposes `http_requests_total`, `http_request_latency_seconds`, `outbox_events_published_total`, `outbox_publish_latency_seconds`, `idempotency_hits_total`, `permission_denials_total`, `rls_blocks_total`. | Yes (additive) |
| W0   | 2026-07-11 | `GET /api/v1/erp/identity/permissions` | **Added.** Returns the global permission catalog (~50+ entries, seeded by `0100_identity` migration). Catalog is global, not tenant-scoped; no auth required in W0. | Yes (additive) |
| W0   | 2026-07-11 | `GET /api/v1/erp/identity/roles` | **Added.** Returns roles for the current tenant. RBAC-gated: requires `identity.role.read` permission and the `x-tenant-id` + `x-user-id` headers. Returns an empty list in W0 (per-tenant roles are seeded in W6's `provision_erp_tenant()`). | Yes (additive) |
| W0   | 2026-07-11 | `GET /api/v1/erp/identity/roles/{role_id}` | **Added.** Returns a single role with its granted permission keys. RBAC-gated: requires `identity.role.read`. 404 on missing / wrong-tenant / soft-deleted role. | Yes (additive) |
| W0   | 2026-07-11 | Middleware order | **Changed.** `ObservabilityMiddleware` is now registered *outside* `IdempotencyMiddleware` so the OTel span covers idempotency processing. The request-id, trace-id, and tenant-id contextvars are set before idempotency runs. | Internal; no client-visible change |
| W0   | 2026-07-11 | Error envelope | **Note.** Every error response uses the same JSON shape: `{ "code", "message", "details", "trace_id" }`. No bare `Exception` reaches the client. Status codes are unchanged for known cases (400, 401, 403, 404, 409, 422, 500). | n/a |
| W0   | 2026-07-11 | Mutating-route contract | **Note.** Every `POST / PUT / PATCH / DELETE` requires three headers in W0: `Idempotency-Key` (UUID, dedup token), `x-tenant-id` (UUID, the GUC for RLS), and `x-user-id` (UUID, the W0 principal stub). W1 swaps `x-user-id` for a real JWT. Mutators that omit any of the three fail with the error envelope and a 400/401 status. | n/a (developer contract) |
| W0   | 2026-07-11 | Soft-delete filter | **Note.** Every list endpoint filters out rows where `deleted_at IS NOT NULL`. RLS policies include the soft-delete check in their `USING` clause so the filter is at the database boundary. The opt-out (`include_deleted=true`) is admin-only and RBAC-gated; not exposed in W0. | Yes (additive in client-visible sense) |
| W0   | 2026-07-11 | Outbox | **Note.** The `outbox_events` table is in the model; the W0 envelope (`shared.outbox.OutboxEvent`, `OutboxStore`) is the in-process writer. The poller and the Kafka producer land in W1; no W0 endpoint publishes to Kafka. | n/a |
| W0   | 2026-07-11 | Observability | **Note.** Every non-system handler runs through `ObservabilityMiddleware`. Per-tenant + per-route Prometheus labels are emitted on every request. Span attributes include `http.method`, `http.target`, `http.status_code`, `tenant.id`. | n/a (operational) |
| W0   | 2026-07-11 | OpenAPI export | **Note.** `docs/openapi/erp.json` is generated by `scripts/dump_openapi.py` and committed; CI re-generates on every PR and diffs against the committed version. Drift blocks merge. | n/a (operational) |
| W0.1 | 2026-07-11 | `GET /api/v1/erp/identity/permissions` | **Changed auth.** Now requires `identity.role.read` permission and a valid `x-tenant-id` + `x-user-id` pair. Previously world-readable (BUG-021). | **Breaking for unauthenticated callers** (the only allowed pattern in v1; the old world-readable behavior was unintended) |
| W0.1 | 2026-07-11 | `GET /api/v1/erp/identity/roles` | **Changed injection.** Now uses `Depends(require_tenant_id)` (typed `UUID`); was reading raw `request.state.tenant_id` (a string) and relying on SQLAlchemy's silent coercion (BUG-019). | Internal; same response shape |
| W0.1 | 2026-07-11 | `GET /ready` | **Changed.** Now checks the `outbox_events` table via `to_regclass('public.outbox_events')` and reports `{"status": "absent"}` if missing (BUG-004). Not a hard 503 — the W0 deliverable is "informational"; W1 promotes it to a hard gate. | Yes (additive field on the response) |
| W0.1 | 2026-07-11 | `Idempotency-Key` header on mutators | **Changed.** The dedup hash is now `sha256(f"{tenant_id}:{key}")` per ADOPT-1; the previous `sha256(key)` was hardening-incomplete (composite PK prevented runtime collision, but the table-level `key_hash` column is no longer globally unique without the tenant prefix). | Internal; no client-visible change |
| W0.1 | 2026-07-11 | Service-account authorization | **Changed.** Service accounts now require an explicit `service_account_scopes` allow-list on the `Principal` (default empty = deny). The W0 service-account check used to return `True` for any permission, which was a privilege-escalation vector (BUG-006). W6 adds the per-tenant allow/deny list. | Yes for any code that relied on the W0 short-circuit (only test code, no real callers) |
| W0.1 | 2026-07-11 | `x-tenant-id` header | **Changed.** The middleware now parses the header to `UUID | None` once and stores on `request.state.tenant_id`. Invalid UUIDs are treated as missing (BUG-008 — fixes the 422/400 mismatch on malformed headers). | Internal |
| W0.1 | 2026-07-11 | Event envelope (W1 prep) | **Note.** The envelope contract is now locked: `event_id, event_type, tenant_id, occurred_at, producer, trace_id` (snake-case, top-level). `producer = "erp-v2@0.1.0"`. Customer IDs are tokenized as `cust:<uuid>`. See `services/erp/src/shared/events/__init__.py` and `docs/adrs/0011-…` / `0012-…`. | n/a (W1 ships the producer; W0 ships the contract) |

## v1 carry-over

Routes that v1 served and v2 does **not** yet replace (still
served by the v1 service on `:8010`):

- `POST /api/v1/erp/orders` — replaced by W1's multiline
  sales-orders endpoint.
- `GET  /api/v1/erp/orders/{id}` — replaced by W1.
- `POST /api/v1/erp/parties` — replaced by W3.
- `GET  /api/v1/erp/parties/{id}` — replaced by W3.
- `POST /api/v1/erp/trade/customs-entries` — replaced by W9.
- `POST /api/v1/erp/connectors/{name}/sync` — replaced by W6.

The Kong shift from `:8010` to `:8001` lands per wave starting
W6. Until then, v1 owns the route.
